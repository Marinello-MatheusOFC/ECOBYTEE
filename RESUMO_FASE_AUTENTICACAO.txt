O QUE FOI FEITO
---------------------------------------------------------

1. AUTENTICACAO REAL (Firebase)
   - Login/Registro agora trocam email/senha por um ID token via
     REST Identity Toolkit (AuthGateway), validado pelo Firebase
     Admin SDK (FirebaseAdminTokenValidator). O UID e extraido
     SOMENTE do token validado - nunca de dados enviados pelo cliente.
   - AutenticacaoService orquestra o fluxo (login, registro).
   - Cookie de sessao ASP.NET Core com claims (AuthClaimTypes:
     Uid, Nome, Email, Perfil, EstabelecimentoId) gerados por
     ClaimsIdentityFactory.
   - Autorizacao por perfil via politicas (AuthPolicies):
     Autenticado, Consumidor, Parceiro, Ong, EmpresaOuOng, Administrador.
   - Onboarding para escolha de perfil apos primeiro login.
   - Usuario documentado no Firestore com ID DO DOCUMENTO = UID
     (fallback para documentos legados). Alinhado as conquistas
     em usuarios/{uid}/conquistas.

2. AUTORIZACAO E PROPRIEDADE DE RECURSOS
   - SolicitacaoService valida o dono da solicitacao e o dono do
     estabelecimento (CancelarAsync / ConfirmarRetiradaAsync).
   - RetiradasController exige perfil Parceiro + estabelecimento proprio.
   - ConsumidorController / SolicitacoesController com politicas por acao.
   - Area Empresa criada (Estabelecimentos, Produtos CRUD,
     Confirmar retiradas) - opera apenas sobre recursos proprios.
   - CMS Admin restrito a Administradores; CRUD de produtos agora
     PERSISTE de verdade (antes Editar/Excluir eram no-op).

   - EcoByte.slnx criado (nao existia) para build/test da solucao.
